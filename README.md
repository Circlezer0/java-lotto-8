# java-lotto-precourse

# 목표
- 헥사고날 아키텍처를 사용함으로써 새로운 아키텍처에 대해 학습하고 계층형 아키텍처와의 차이점을 이해
- 도메인 객체들에서 getter, setter를 최대한 사용하지 않도록 구현
- 확장을 과도하게 고려하지 않는 설계 (YAGNI 원칙) 적용

# 추가 문제 정의
1. 입력 가능한 구입 금액의 범위는 10억으로 제한한다.
2. 로또는 1장 이상 구매할 수 있어야 한다.
3. 구입금액은 0원을 초과해야 한다. (divided by 0 방지)
4. 로또는 항상 정렬된 숫자들을 가지고 있어야 한다.

# 구현해야 할 사항

## 기능 정의
1. 입출력 처리
- [x] 구입 금액 안내문 출력 후 금액 입력
- [x] 로또 구매 개수, 구매한 로또들의 번호 출력
- [x] 당첨 번호 입력 안내문 출력 후 당첨 번호 입력
- [x] 보너스 번호 입력 안내문 출력 후 보너스 번호 입력
- [x] 당첨 통계 출력
- [x] 소수점 1자리수 단위의 총 수익률 출력
- [x] 입력에 실패 시 오류 문구를 출력하고 입력 재시도

2. 로또 관련
- [x] 로또 번호 6개를 랜덤으로 생성하는 기능
- [x] 로또 번호의 당첨 결과를 확인하는 기능
- [x] 당첨 통계 기능
- [x] 수익률 계산 기능

3. 예외 목록
- [x] 구입 금액이 0원 이하이거나 10억 초과일 때
- [x] 구입 금액이 1,000원 단위가 아닐 때
- [x] 로또를 1장도 구매하지 못할 때
- [x] 번호가 6개가 아닐 때
- [x] 번호가 1~45 범위가 아닐 때
- [x] 당첨번호 입력 시 숫자가 아니거나, 개수가 6개가 아니거나, 범위가 1~45가 아닐 때
- [x] 당첨 번호와 보너스 번호가 중복될 때

## 도메인 분류

1. 로또 (Lotto)
   - 담당 기능
     - 6개의 로또 번호 보관
     - 로또 번호의 유효성 검사
   - 처리할 예외
     - 로또 번호 중복 예외
     - 번호 개수 예외
     - 번호 범위 예외

2. 당첨 번호 (WinningNumber)
   - 담당 기능
     - 당첨 번호와 보너스 번호 보관
     - 당첨 결과 확인
   - 처리할 예외
     - 당첨 번호와 보너스 번호 중복 예외
     - 번호 개수 예외
     - 번호 범위 예외

3. 로또 등급 (PrizeTier)
    - 담당 기능
      - 맞춘 번호 개수와 보너스 번호 포함 여부에 따른 등급 결정
      - 등급별 상금 보관
    - 처리할 예외
      - 없음

# 아키텍처 개요

헥사고날 스타일을 참고하여 작성하였습니다.
헥사고날 아키텍처에 대한 학습이 목표였기 때문에 application 계층에서 service와 usecase를 구분하였고, port input/output을 분리하여 구현해보았습니다.

- domain: 로또 규칙과 값 객체가 있는 순수한 영역
    - `Lotto`, `WinningNumber`, `PrizeTier`, `Money`, `Yield`, `LottoNumberValidator`, `LottoGameRule`
- **application**: 유즈케이스를 제공하는 서비스 계층
    - `LottoService` – 로또 구매, 당첨 번호 생성, 결과 집계, 수익률 계산
    - 외부 라이브러리를 사용하는 기능을 추상화: `NumberGenerator`
- **adapter**
    - inbound(입력/UI): 콘솔에서 값을 읽고, 서비스 호출 후 결과를 출력
        - `LottoController`, `InputView`, `OutputView`
    - outbound(외부 연동): 실제 랜덤 숫자를 만드는 구현체
        - `RandomNumberGenerator`


# 예외 처리 정책
- 모든 비즈니스/입력 오류는 LottoException extends IllegalArgumentException 으로 감싼다.
- 예외 메시지는 공통 prefix인 "[ERROR] " 로 시작한다.
- 콘솔 어댑터(LottoController)는 입력 과정에서 예외가 발생하면 해당 입력만 재시도한다.
  - 당첨 번호 + 보너스 번호를 입력받고, WinningNumber 생성 시 예외가 발생하면 당첨 번호부터 다시 입력받는다.
- 예외 종류는 역할에 따라 두 그룹으로 나뉜다. 
  - AdapterErrorCode: 콘솔 파싱, 랜덤 숫자 생성 파라미터 오류 
  - DomainErrorCode: 로또 규칙 위반, 금액 규칙 위반, 당첨 번호 규칙 위반
