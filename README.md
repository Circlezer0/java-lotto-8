# java-lotto-precourse

# 목표
- 헥사고날 아키텍처를 사용함으로써 새로운 아키텍처에 대해 학습하고 계층형 아키텍처와의 차이점을 이해
- 도메인 객체들에서 getter, setter를 최대한 사용하지 않도록 구현
- 확장을 과도하게 고려하지 않는 설계 (YAGNI 원칙) 적용

# 추가 문제 정의
1. 입력 가능한 구입 금액의 범위는 10억으로 제한한다.
2. 로또는 1장 이상 구매할 수 있어야 한다.
3. 구입금액은 0원을 초과해야 한다. (divided by 0 방지)
4. 로또는 항상 정렬된 숫자들을 가지고 있어야 한다.

# 구현해야 할 사항

## 기능 정의
1. 입출력 처리
- [ ] 구입 금액 안내문 출력 후 금액 입력
- [ ] 로또 구매 개수, 구매한 로또들의 번호 출력
- [ ] 당첨 번호 입력 안내문 출력 후 당첨 번호 입력
- [ ] 보너스 번호 입력 안내문 출력 후 보너스 번호 입력
- [ ] 당첨 통계 출력
- [ ] 소수점 1자리수 단위의 총 수익률 출력

2. 로또 관련
- [ ] 로또 번호 6개를 랜덤으로 생성하는 기능
- [ ] 로또 번호의 당첨 결과를 확인하는 기능
- [ ] 당첨 통계 기능
- [ ] 수익률 계산 기능

3. 예외 목록
- [ ] 구입 금액이 0원 이하이거나 10억 초과일 때
- [ ] 구입 금액이 1,000원 단위가 아닐 때
- [ ] 로또를 1장도 구매하지 못할 때
- [ ] 번호가 6개가 아닐 때
- [ ] 번호가 1~45 범위가 아닐 때
- [ ] 당첨번호 입력 시 숫자가 아니거나, 개수가 6개가 아니거나, 범위가 1~45가 아닐 때
- [ ] 당첨 번호와 보너스 번호가 중복될 때

## 도메인 분류

1. 로또 (Lotto)
   - 담당 기능
     - 6개의 로또 번호 보관
     - 로또 번호의 유효성 검사
   - 처리할 예외
     - 로또 번호 중복 예외
     - 번호 개수 예외
     - 번호 범위 예외

2. 당첨 번호 (Winning)
   - 담당 기능
     - 당첨 번호와 보너스 번호 보관
     - 당첨 결과 확인
   - 처리할 예외
     - 당첨 번호와 보너스 번호 중복 예외
     - 번호 개수 예외
     - 번호 범위 예외

3. 로또 등급 (LottoRank)
    - 담당 기능
      - 맞춘 번호 개수와 보너스 번호 포함 여부에 따른 등급 결정
      - 등급별 상금 보관
    - 처리할 예외
      - 없음
